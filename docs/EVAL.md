# Оценка качества

Результаты прогонов `eval.run_search` и `eval.run_generation`. Запросы — `backend/eval/queries.yaml` (24 запроса: 18 с ожидаемой операцией, 6 без) и `backend/eval/requests.yaml` (5 запросов генерации). Наборы написаны автором прототипа, поэтому цифры оптимистичны: см. [NOTES](NOTES.md).

Запуск:

```bash
docker compose exec backend python -m eval.run_search
docker compose exec backend python -m eval.run_generation --repeats 3
```

Результаты пишутся в `backend/eval/results/` (в репозиторий не попадают).

## Поиск

Метрики считаются без отсечения порогом по первым 5 кандидатам после фильтра (тип станка, тип операции, диалект).
`decision_accuracy` — доля запросов, где решение «найдено / не найдено» верно при пороге.

| Дата | Эмбеддинги / реранкер | hit@1 | hit@3 | MRR | decision_accuracy | порог в прогоне | рекомендуемый порог | примечание |
|---|---|---|---|---|---|---|---|---|
| 14.10.2026 | хеши слов (`mock`) | 1.00 | 1.00 | 1.00 | 0.83 | 0.5 | 0.447 | верные кандидаты до 0.5365, отрицательные от 0.3581: порог не разделяет |

Вывод по хеш-эмбеддингам: ранжирование внутри отфильтрованного списка верное (в базе по 1–2 операции каждого типа на диалект), но расстояние как мера «найдено / не найдено» ненадёжно: перефразированный запрос «Проточить гладкий вал в размер 46…» (0.5365) отсекается порогом, а посторонний запрос про сверление пушечным сверлом (0.3581) проходит.
