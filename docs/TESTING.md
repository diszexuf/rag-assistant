# Проверка работоспособности: что вводить

Пошаговые проверки с готовыми значениями для полей. Тексты описаний можно копировать как есть.

Перед началом: контейнеры запущены, база наполнена (`python -m seed.seed`), клиент открыт на http://localhost:5173. Команды — в [README](../README.md).

**Что считать успехом.** Источники и расстояния определяются поиском и повторяются от запуска к запуску. Текст программы пишет модель, и он каждый раз немного разный — сверяйте структуру, а не точное совпадение.

## 0. Система запустилась

Откройте http://localhost:8000/api/health.

Ожидается: `{"status":"ok","llm_provider":"gigachat","embedding_provider":"mock"}`.

На странице клиента слева должны быть два списка (станок, материал) и кнопка «Начать новый чат». Если списки пусты — база не наполнена.

## 1. Всё находится в базе знаний

| Поле | Значение |
|---|---|
| Станок | Токарный станок с ЧПУ Fanuc 0i-TD |
| Материал | Конструкционная сталь |

Нажмите «Начать новый чат», затем заполните две операции (вторую строку добавляет кнопка «Добавить операцию»).

| № | Тип | Описание |
|---|---|---|
| 1 | Подрезка торца | `Подрезка торца заготовки диаметром 60 мм проходным резцом T0101, скорость резания 120 м/мин, подача 0.15 мм/об` |
| 2 | Сверление | `Сверление центрального отверстия диаметром 20 мм на глубину 30 мм сверлом T1111, цикл глубокого сверления` |

Нажмите «Сгенерировать программу».

Ожидается:

- под запросом появляется строка со стадией и таймером: «Поиск похожих операций», «Модель составляет программу», «Проверка валидатором»; возможно «Модель исправляет ошибки, попытка 1»;
- через 10–40 секунд справа открывается программа с меткой «На основе базы знаний»;
- в источниках: обе операции «из базы знаний», программа «Втулка с центральным отверстием (Fanuc)», расстояния около 0,12 и 0,21;
- в программе есть `T0101`, проход `G1 X-2`, `T1111`, цикл `G83`, в конце `M30`.

Что проверить глазами: подвод к торцу должен быть около `X62`, а глубина сверления `Z-30`. Если стоит `X84` или `Z-42` — модель оставила числа из образца; это известная слабость, а не поломка.

## 6. Ручная правка и валидатор

Откройте любую программу для станка **Sinumerik** (например, из проверки 2). В поле текста программы замените всё содержимое на:

```
G54 G40 G71 G90 G95
T9 D1
G97 S4000 M3
G0 X76 Z0 M8
G1 X-2 F0.15
G0 Z2
M5
```

Нажмите «Сохранить изменения».

Ожидается:

- в списке версий появляется «2 — ручная правка, ошибок: 3»;
- в отчёте три замечания:
  - «Строка 2. Инструмент в позиции 9 отсутствует в магазине станка (есть: 1, 2, 3, 4, 5)»;
  - «Строка 3. Частота вращения 4000 об/мин превышает предел станка 2500 об/мин»;
  - «Строка 7. Программа не завершена командой конца программы (M30, M2, M17, RET)»;
- правка сохранена несмотря на ошибки; через список версий можно вернуться к версии 1.

### Остальные проверки валидатора

Вставьте строку в середину программы для станка **Fanuc** (не после `M30`, иначе добавится замечание о конце программы), сохраните и сверьте замечание.

| Что ввести | Ожидаемое замечание |
|---|---|
| `G128 X10` | Команда G128 отсутствует в диалекте «Fanuc, токарная обработка» |
| `G0 X= Z5` | Синтаксическая ошибка: не удалось разобрать… |
| `T0909` | Инструмент в позиции 9 отсутствует в магазине станка (есть: 1, 2, 3, 4, 11) |
| `G97 S9000 M3` | Частота вращения 9000 об/мин превышает предел станка 3000 об/мин |
| `G50 S5000` | Ограничение оборотов 5000 об/мин превышает предел станка 3000 об/мин |
| `G96 S9000 M3` | Замечания нет: при `G96` число после `S` — скорость резания, а не обороты |
| Удалить строку с `M30` | Программа не завершена командой конца программы (M30, M2, M99) |

## 7. Поведение формы и чатов

| Действие | Ожидается |
|---|---|
| Оставить описание пустым или ввести два символа | Кнопка «Сгенерировать программу» неактивна |
| Нажать «Удалить» у единственной операции | Кнопка неактивна: в запросе должна быть хотя бы одна операция |
| Во время генерации попробовать отправить второй запрос | Кнопка неактивна до завершения запуска |
| Открыть другой чат в списке слева | Показываются его запросы и последняя программа |
| Нажать «Открыть программу» у более раннего ответа | Справа открывается программа того ответа |
| Нажать «Удалить» у чата | Чат исчезает из списка вместе с его программами |

## 8. Работа без GigaChat

В `.env` поставьте `LLM_PROVIDER=mock` и перезапустите бэкенд:

```bash
docker compose up -d
```

Повторите проверку 1. Ожидается: программа появляется за секунду и состоит из найденных фрагментов без изменений, пояснение начинается со слова «Заглушка». Источники те же, что с живой моделью, — поиск от модели не зависит.

Верните `LLM_PROVIDER=gigachat` и перезапустите бэкенд тем же способом.

## 9. Автоматические тесты

```bash
docker compose exec backend pytest
```

Ожидается: `22 passed`. Тесты не обращаются к GigaChat и не зависят от ключа.

## Если что-то пошло не так

| Признак | Причина и что делать |
|---|---|
| «Генерация не удалась: GigaChat недоступен…» | Нет сети, истёк ключ или нет сертификата в `backend/certs/`. Проверка: `docker compose exec backend python -m app.llm.check` (чат должен ответить; ошибка 402 на эмбеддингах ожидаема) |
| «Генерация не удалась: Сервер был перезапущен во время генерации» | Бэкенд перезагрузился из-за правки файлов в `backend/`. Повторите запрос |
| «Модель не вернула текст программы» | Модель ответила без блока кода. Повторите запрос |
| Все операции «источника нет» | База не наполнена либо сменили `EMBEDDING_PROVIDER` без перезагрузки базы: `python -m seed.seed --reset` |
| Списки станков пусты | Не выполнены миграции или сид-скрипт |
