# План разработки прототипа RAG-помощника технолога

## Контекст

ТЗ на MVP: `C:\Users\user\Documents\prototypes_vault\Диплом\ТЗ MVP.md`. Прототип реализует ядро MVP в минимальном объёме. Акцент — на RAG: поиск похожих операций и программ в базе знаний и генерация УП через API GigaChat. Дополнительный функционал (раздел 10 ТЗ) в прототип не входит.

Принятые решения:

- **Порядок:** сквозной срез. Сначала тонкий работающий пайплайн на заглушке LLM, затем углубление модулей.
- **Обработка:** только токарная. Фрезерная добавляется позже новыми описаниями диалектов и данными, без изменения архитектуры.
- **GigaChat:** единственная используемая модель — базовая `GigaChat`. Тесты идут на заглушке и от ключа не зависят.
- **Конвертер исключён из плана** и переведён в разряд будущих функций. В коде остаётся заглушка с тем же контрактом: операция, найденная только на другом диалекте, помечается «источника нет». Старый конвертер AnyCNC (`C:\Users\user\Documents\CONVERTER`) — образец на будущее.
- **Валидатор заморожен.** Пять проверок и цикл доработки уже реализованы на этапе 1 и остаются в пайплайне, но дальше не развиваются.
- **Данные:** часть УП берётся из лабораторных примеров AnyCNC (`projects/model/examples`), их можно отправлять в GigaChat.

Окружение: Docker и Compose, Node 24. Бэкенд работает в контейнере на Python 3.12.

## Объём

| Что | Объём прототипа |
|---|---|
| Диалекты | 2 описания: токарный Fanuc, токарный Sinumerik |
| Станки | 2, по одному на диалект |
| Инструмент | 5–6 позиций в карточке станка, отдельного каталога нет |
| УП в базе знаний | 5–6 УП, 10–12 операций |
| Типы операций | 4: наружное точение, подрезка торца, сверление, нарезание резьбы |
| Документация | Один короткий файл на диалект |
| Валидатор | 5 проверок, готов; не развивается |
| Конвертер | Заглушка; вне плана |
| Редактор УП | Текстовое поле и список замечаний с номерами строк |
| Тестовые запросы | 5, покрывают три вида источников |

Без изменений относительно ТЗ: запрос со списком операций, поиск с фильтром и порогом, три вида источников, сборка УП одним вызовом, цикл доработки, фоновые запуски с SSE и таймером, чаты, версии УП, ручная правка.

## Этапы

### Этап 0. Каркас

- Git-репозиторий, `docker-compose.yml` с PostgreSQL + pgvector и бэкендом.
- FastAPI с `/api/health`, конфигурация, async SQLAlchemy, Alembic.
- Каркас фронтенда на Vite с прокси на бэкенд.
- `.env.example`, README с командами запуска.

Готово, когда: `docker compose up` поднимает БД и API, `/api/health` отвечает, фронтенд открывается и показывает состояние API.

### Этап 1. Сквозной срез на заглушке

Каждый модуль в минимальном объёме, но по контрактам из раздела 6 ТЗ.

- **Модуль УП (тонко):** формат описания диалекта, описание токарного Fanuc; парсер кадров; три проверки (синтаксис, неизвестная команда, нет конца программы); `convert` — заглушка, возвращающая все кадры в `unconverted`.
- **LLM-шлюз:** интерфейсы `ChatModel` и `EmbeddingModel`; заглушка в двух режимах:
  - сценарный — очередь заранее заданных ответов, для тестов;
  - демонстрационный — собирает УП из фрагментов-источников из промпта, чтобы прототип показывал осмысленный результат без API;
  - эмбеддинги заглушки — детерминированные, на хешах слов.
- **База знаний:** таблицы одной миграцией; загрузка УП с разметкой операций; `search_operations` с фильтром, порогом и ослаблением фильтра; чтение справочников.
- **Данные:** 2 станка, 3–4 УП, около 8 операций; сид-скрипт.
- **Оркестратор:** источник по каждой операции, сборка УП одним вызовом, цикл доработки с досрочной остановкой; фоновые запуски, стадии в БД, поток событий для SSE; пометка зависших запусков при старте.
- **Приложение:** чаты (станок, материал), приём запроса со списком операций, версии УП, сохранение ручной правки с валидацией, эндпоинт SSE.
- **Клиент:** один экран: список чатов, создание чата, форма операций, ход генерации с таймером и таймаутом, текстовое поле УП, отчёт валидатора, источники.

Готово, когда: в браузере создаётся чат, отправляется запрос из двух операций, видны стадии, приходит УП с отчётом и источниками, ручная правка сохраняется новой версией. Тесты оркестратора на сценарной заглушке покрывают три вида источников, цикл доработки, таймаут и отказ модели.

Этап 1 выполнен. Сверх плана в нём сделаны адаптер GigaChat, разбор Sinumerik и все пять проверок валидатора.

### Этап 2. Поиск

- Документация диалектов: загрузка, нарезка на фрагменты, поиск и передача найденных фрагментов в промпт.
- В интерфейсе: текст найденного фрагмента по каждой операции, чтобы было видно, на что опиралась модель.

Эмбеддинги остаются локальными, на хешах слов: поиск по совпадению слов. Смысловой поиск включается позже оплатой пакета эмбеддингов GigaChat и переменной `EMBEDDING_PROVIDER=gigachat`, без изменения кода.

Готово, когда: для операции без источника в промпт попадает фрагмент документации, а найденный фрагмент УП виден в интерфейсе.

### Этап 3. Генерация через GigaChat

- Промпты: модель берёт размеры, режимы и инструмент из описания операции, а не копирует фрагмент-источник; операции без источника пишет по документации.
- Тесты адаптера на подменённом HTTP: токен, повторы, ошибки.
- Журнал вызовов: длительность и число токенов по каждому запуску.

Готово, когда: на тестовых запросах размеры в УП соответствуют запросу; результаты прогона зафиксированы.

### Этап 4. Данные

- Довести базу до 5–6 УП и 10–12 операций четырёх типов.
- 5 тестовых запросов с ожидаемым источником по каждой операции.

Каждая УП вычитывается человеком.

### Этап 5. Приёмка

- Сценарии из раздела 11 ТЗ в объёме прототипа, включая таймаут и обновление страницы во время генерации.
- Протокол прогона тестовых запросов в `docs/`.
- Заметки для плана разработки: где пайплайн разошёлся с ТЗ, что упрощено, что вынесено в будущие функции (конвертер, развитие валидатора).

## Оценка

На оставшиеся этапы — около 4–5 часов работы в две сессии. Оценка грубая; главные риски — подбор промптов на живом GigaChat и качество поиска на малом объёме данных.

- `docker compose up -d --build`; `docker compose exec backend alembic upgrade head`; `docker compose exec backend python -m seed.seed`.
- `docker compose exec backend pytest`.
- `npm run dev` во `frontend/`, сценарий в браузере: создание чата, запрос, стадии, УП, правка.
- С ключом: `LLM_PROVIDER=gigachat` в `.env`, `python -m app.llm.check`, затем тот же сценарий.
